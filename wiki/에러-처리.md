# 에러 처리

## try / catch / throw

```bang
try {
    let x = 10 / 0
    print("여기는 실행되지 않음")
} catch e {
    print("잡음:", e.message)
}
print("계속 진행")
```

출력:

```text
잡음: 0으로 나눌 수 없음
계속 진행
```

- `throw 값`은 아무 값이나 던질 수 있습니다. 잡으면 던진 값이 **그대로** `e`에 들어옵니다.
- 내장 에러(0 나눗셈, 없는 키, 파일 없음 등)를 잡으면 `e`는 맵 `{kind, message, line, col}`입니다.
- 에러는 함수 호출을 거슬러 올라가며 가장 가까운 `catch`가 잡습니다.
- `finally`는 없습니다.

```bang
try {
    throw {"code": 404, "msg": "없음"}
} catch e {
    print(e.code, e.msg)
}

fn parse_age(s) {
    try {
        return int(s)
    } catch e {
        throw f"나이 형식이 틀림: {s}"
    }
}
try {
    parse_age("열")
} catch e {
    print(e)
}
```

출력:

```text
404 없음
나이 형식이 틀림: 열
```

`print(e)`로 내장 에러를 찍으면 맵 전체가 나옵니다. 메시지만 원하면 `e.message`를 쓰세요.

## 에러 종류 (`e.kind`)

| kind | 언제 | 예 |
|---|---|---|
| `zero_division` | 0으로 나눔 | `1 / 0`, `idiv(1, 0)`, `5 % 0` |
| `overflow` | 정수가 64비트 범위를 넘음 | `9223372036854775807 * 2` |
| `index` | 인덱스 범위 초과 | `[1][5]` |
| `key` | 맵에 없는 키 읽기 | `{"a": 1}["b"]`, `m.b` |
| `type` | 연산할 수 없는 타입 조합, 타입 힌트 불일치 | `1 + "x"` |
| `argument` | 내장 함수 인자가 잘못됨 | `sqrt("x")` |
| `value` | 형식은 맞지만 값이 잘못됨 | `int("abc")`, `json_parse("{bad")` |
| `io` | 파일·네트워크·프로세스 실패 | `read_file("/없는/파일")` |
| `assertion` | `assert`/`assert_eq` 실패 | `assert(false, "확인 실패")` |
| `import` | 모듈을 찾지 못함, 순환 import | `import("없는모듈")` |
| `error` | 그 밖의 경우 (작업 밖으로 나온 `throw` 값 등) | |

```bang
let cases = [
    fn() { return 1 / 0 },
    fn() { return 9223372036854775807 * 2 },
    fn() { return [1][5] },
    fn() { return {"a": 1}["b"] },
    fn() { return 1 + "x" },
    fn() { return sqrt("x") },
    fn() { return int("abc") },
    fn() { assert(false, "확인 실패") },
]
for c in cases {
    try {
        c()
    } catch e {
        print(e.kind, "|", e.message)
    }
}
```

출력:

```text
zero_division | 0으로 나눌 수 없음
overflow | 정수 오버플로: * 결과가 64비트 범위를 벗어남
index | 인덱스 범위 초과: 5 (길이 1)
key | 맵에 키 'b' 없음 (없을 수 있으면 get(m, k, 기본값) 또는 has(m, k))
type | +: Int + Str 연산 불가
argument | 부동소수점 필요, Str 발견
value | int 변환 실패: 'abc'
assertion | assertion 실패: 확인 실패
```

## 골라 잡고 나머지는 다시 던지기

```bang
fn read_config(path) {
    try {
        return json_parse(read_file(path))
    } catch e {
        if e.kind == "io" {
            return {}            // 파일이 없으면 빈 설정
        }
        throw e                  // 그 밖의 에러(잘못된 JSON 등)는 위로
    }
}
print(read_config("없는파일.json"))
```

출력:

```text
{}
```

다시 던진 에러가 끝내 잡히지 않으면, 원래 에러의 메시지와 위치로 보고됩니다.

## 에러 메시지 읽기

잡히지 않은 에러는 위치 `[줄:열]`, 메시지, 해당 소스 줄과 `^` 표시를 stderr에 출력하고 종료 코드 1로 끝납니다.

```bang
fn load(path) {
    return read_file(path)
}
let cfg = load("config.json")
```

에러 출력:

```text
[2:12] 런타임 오류: read_file(): 'config.json': No such file or directory (os error 2)
  |
  2 |     return read_file(path)
  |            ^
```

에러가 import한 모듈 안에서 났다면 `[모듈경로 줄:열]`처럼 파일 이름이 함께 나오고, 그 파일의 소스 줄을 보여 줍니다. `spawn`·`parallel_map` 안에서 난 에러도 원래 난 줄을 가리킵니다.

에러는 세 단계에서 납니다.

| 단계 | 표시 | 예 |
|---|---|---|
| 파스 | `파스 오류` | 괄호 짝이 안 맞음, 한 줄에 문장 두 개 |
| 리졸브 (실행 전 검사) | `리졸브 오류` | 정의되지 않은 이름, 인자 수 불일치 |
| 런타임 | `런타임 오류` | 0 나눗셈, 없는 키, 파일 없음 |

파스·리졸브 오류는 프로그램이 **한 줄도 실행되기 전에** 납니다.

```bang
print("이 줄도 실행되지 않음")
print(undefined_name)
```

에러 출력:

```text
[2:7] 리졸브 오류: 정의되지 않은 변수: 'undefined_name'
  |
  2 | print(undefined_name)
  |       ^
```

사용하지 않은 변수 같은 **경고**도 stderr에 나오지만 실행은 계속됩니다.

## assert

```bang
fn area(w, h) {
    assert(w >= 0 and h >= 0, "크기는 음수일 수 없음")
    return w * h
}
assert_eq(area(2, 3), 6)
try {
    assert_eq(area(2, 3), 7)
} catch e {
    print(e.kind, "|", e.message)
}
```

출력:

```text
assertion | assert_eq 실패: 기대 7, 실제 6
```

`assert_eq`는 [`bang test`](도구#bang-test)에서 주로 씁니다.

## 원칙: 조용히 넘어가지 않는다

bang은 잘못된 상황을 조용히 `nil`이나 0으로 바꾸지 않고 에러로 알립니다: 없는 맵 키, 정수 오버플로, 숫자가 아닌 값과의 산술, 채널로 함수 보내기, 버려진 `push` 결과 등. 처음엔 엄격하게 느껴질 수 있지만, 버그가 생긴 바로 그 줄에서 알 수 있습니다.
