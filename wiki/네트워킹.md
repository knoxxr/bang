# 네트워킹

## HTTP 클라이언트

<!-- norun -->
```bang
let r = http_get("https://api.github.com/repos/knoxxr/bang")
print(r.status)                     // 200
print(r.headers["content-type"])    // 헤더 이름은 소문자
let repo = json_parse(r.body)
print(repo.full_name)
```

| 함수 | 설명 |
|---|---|
| `http_get(url)` | GET |
| `http_post(url, 본문[, 헤더[, 옵션]])` | POST |
| `http_request(메서드, url[, 본문[, 헤더[, 옵션]]])` | 아무 메서드 (`"PUT"`, `"DELETE"`, ...) |

세 함수 모두 `{status, headers, body}` 맵을 돌려줍니다.

- **본문**: 맵·리스트는 JSON으로 바뀌어 `application/json`으로 갑니다. 문자열은 `text/plain`, 바이트는 `application/octet-stream`, `nil`은 본문 없음. `Content-Length`는 자동입니다.
- **헤더**: `{"Authorization": "Bearer ..."}`처럼 맵으로 줍니다. 값에 줄바꿈이 있으면 에러(헤더 주입 방지).
- **상태 코드**: 404·500도 에러가 아니라 `status`로 돌려줍니다. 연결 실패·TLS 실패·대기 시간 초과·중간에 끊긴 응답은 `io` 에러입니다(잘린 본문을 조용히 돌려주지 않습니다).
- **대기 시간**: 기본 10초입니다. 오래 걸리는 API는 옵션 `{"timeout_ms": 120000}`으로 늘리세요(`0`은 무제한).
- **리다이렉트**는 따라가지 않습니다. `status`가 301/302이면 `headers.location`을 보고 다시 요청하세요.
- `https://`를 지원합니다. 인증서는 항상 검증하며 끄는 옵션은 없습니다.

<!-- norun -->
```bang
let created = http_post("https://api.example.com/items", {"name": "방", "qty": 2})
let raw = http_post(url, "plain text", {"Authorization": "Bearer TOKEN"})
let gone = http_request("DELETE", "https://api.example.com/items/7")
```

### 옵션

마지막 인자로 옵션 맵을 줍니다. 본문이나 헤더가 없으면 그 자리는 `nil`로 둡니다. `http_get`에는 옵션이 없으므로 `http_request("GET", url, nil, nil, 옵션)`을 쓰세요.

| 키 | 값 | 뜻 |
|---|---|---|
| `timeout_ms` | 0 이상의 정수 (기본 10000, 0 = 무제한) | 연결·전송·응답 대기 각각의 상한. 스트리밍에서는 "다음 데이터가 올 때까지"의 상한 |
| `on_line` | `fn(line)` | 성공(2xx) 응답 본문을 **받는 대로 한 줄씩** 넘김. 이때 결과의 `body`는 `nil` |

- `on_line` 함수가 `false`를 돌려주면 그 자리에서 수신을 멈춥니다. `throw`하면 요청 밖의 `catch`로 그 값이 그대로 갑니다.
- 404·429·500 같은 응답은 콜백으로 넘기지 않고 평소처럼 `body`에 모아 줍니다. `status`를 확인하세요.
- 모르는 옵션 이름이나 잘못된 값은 무시되지 않고 `argument` 에러입니다.

### 여러 API를 동시에 부르기

bang이 가장 잘하는 일입니다. 순차 코드와 모양이 같습니다.

<!-- norun -->
```bang
let urls = [
    "https://api.github.com/repos/rust-lang/rust",
    "https://api.github.com/repos/python/cpython",
    "https://api.github.com/repos/golang/go",
]
let stars = parallel_map(urls, fn(u) {
    return json_parse(http_get(u).body).stargazers_count
})
print(stars)        // 세 요청이 동시에 나가고, 결과는 urls 순서대로
```

한 요청이 실패하면 나머지가 끝난 뒤 첫 에러를 던집니다. 실패를 개별로 처리하려면 함수 안에서 `try`로 감싸 `nil` 같은 값을 돌려주세요.

### LLM API 부르기 (병렬 + 스트리밍)

LLM API는 응답이 길게는 몇 분 걸리고, 답을 만들어지는 대로 조금씩 보내 주는 스트리밍(SSE)을 지원합니다. 저장소의 [`examples/llm_fanout.bang`](https://github.com/knoxxr/bang/blob/main/examples/llm_fanout.bang)이 두 가지를 모두 보여 줍니다(Anthropic Messages API 기준, `ANTHROPIC_API_KEY` 필요).

질문 여러 개를 동시에 보내기:

<!-- norun -->
```bang
fn ask(question) {
    let body = {
        "model": "claude-opus-5-5",
        "max_tokens": 16000,
        "messages": [{"role": "user", "content": question}],
    }
    let headers = {"x-api-key": env_get("ANTHROPIC_API_KEY"), "anthropic-version": "2026-10-21"}
    let r = http_post("https://api.anthropic.com/v1/messages", body, headers, {"timeout_ms": 300000})
    if r.status != 200 { throw {"status": r.status, "body": r.body} }
    let text = ""
    for block in json_parse(r.body).content {
        if block.type == "text" { text += block.text }
    }
    return text
}

let answers = parallel_map(["질문 1", "질문 2", "질문 3"], ask)   // 세 요청이 동시에 나감
```

답을 생성되는 대로 받기 — 서버가 보내는 `data: {...}` 줄을 `on_line`으로 받아 글자 조각(`text_delta`)만 모읍니다:

<!-- norun -->
```bang
let headers = {"x-api-key": env_get("ANTHROPIC_API_KEY"), "anthropic-version": "2026-10-21"}
let text = ""
fn on_event(line) {
    if not starts_with(line, "data: ") { return nil }
    let ev = json_parse(line[6:])
    if ev.type == "content_block_delta" and ev.delta.type == "text_delta" {
        text += ev.delta.text
    }
}
let body = {"model": "claude-opus-5-5", "max_tokens": 64000, "stream": true,
    "messages": [{"role": "user", "content": "짧은 시를 써 줘"}]}
http_post("https://api.anthropic.com/v1/messages", body, headers, {"timeout_ms": 120000, "on_line": on_event})
print(text)
```

재시도·속도 제한(429) 처리처럼 서비스마다 다른 부분은 언어에 넣지 않고 스크립트나 패키지로 둡니다.

### 한계

- 루트 인증서는 바이너리에 내장된 Mozilla 목록만 씁니다. OS 인증서 저장소를 읽지 않으므로 **사내 프록시처럼 자체 인증 기관(CA)을 쓰는 환경에서는 https가 실패합니다**.
- `body`는 문자열입니다. UTF-8이 아닌 응답은 깨진 문자(`�`)로 바뀝니다.
- HTTP 프록시, HTTP/2, 클라이언트 인증서(mTLS)는 지원하지 않습니다. 스트리밍은 줄 단위(`on_line`)만 됩니다.

## TCP 서버 — 연결마다 작업 하나

가장 단순한 서버입니다. 연결마다 `spawn`하므로 느린 클라이언트가 다른 연결을 막지 않습니다.

<!-- norun -->
```bang
fn handle(conn) {
    tcp_set_timeout(conn, 5000)                      // 멈춘 클라이언트가 작업을 영원히 붙잡지 않게
    let req = tcp_read_until(conn, "\r\n\r\n")       // 요청 헤더 끝까지 읽기
    let path = regex_groups(req, "^GET (\\S+)")[1]
    let body = json_stringify({"path": path, "ok": true})
    let size = len(bytes_from_str(body))             // Content-Length는 바이트 수!
    tcp_write(conn, f"HTTP/1.1 200 OK\r\nContent-Type: application/json\r\nContent-Length: {size}\r\nConnection: close\r\n\r\n{body}")
    tcp_close(conn)
}

let server = tcp_listen("127.0.0.1:8080")
print("http://127.0.0.1:8080 에서 대기 중")
while true {
    let conn = tcp_accept(server)
    spawn handle(conn)
}
```

```text
$ curl http://127.0.0.1:8080/users/7
{"path":"/users/7","ok":true}
```

> `len(문자열)`은 **문자 수**입니다. HTTP의 `Content-Length`는 **바이트 수**이므로 한글이 들어간 본문에는 `len(bytes_from_str(body))`를 써야 합니다.

| 함수 | 설명 |
|---|---|
| `tcp_listen("주소:포트")` | 리스너 |
| `tcp_accept(리스너)` | 연결이 올 때까지 기다려 연결 반환 |
| `tcp_connect("주소:포트")` | 클라이언트로 접속 |
| `tcp_read(c)` | 도착한 만큼 읽기 (최대 4096바이트, 끝나면 `""`) |
| `tcp_read_until(c, 표식)` | 표식이 나올 때까지 모아 읽기 |
| `tcp_read_bytes(c)` | 바이트로 읽기 |
| `tcp_write(c, 데이터)` | 문자열 또는 바이트 쓰기 |
| `tcp_send_file(c, 경로)` | 파일을 그대로 전송 (이미지 등 바이너리 무손실) |
| `tcp_set_timeout(c, ms)` | 읽기 타임아웃 |
| `tcp_close(c)` | 닫기 |

작업은 탄력적인 스레드 풀에서 돌아 동시 연결 수백 개까지 처리합니다(최대 512 작업자).

## 이벤트 루프 서버 — serve_event

유휴 keep-alive 연결이 아주 많을 때(C10K) 쓰는 방식입니다. 한 스레드가 모든 연결을 지켜보다가 요청이 완성된 연결만 처리합니다.

<!-- norun -->
```bang
serve_event("127.0.0.1:8080", fn(req) {
    let body = "hello from serve_event"
    return f"HTTP/1.1 200 OK\r\nContent-Length: {len(body)}\r\n\r\n{body}"
})
```

- 핸들러는 요청 문자열을 받아 **완전한 HTTP 응답 문자열**을 돌려줍니다. keep-alive가 자동 처리됩니다.
- **단일 스레드**입니다. 핸들러 안에서 무거운 계산이나 블로킹 호출을 하면 그동안 모든 연결이 멈춥니다. CPU 작업이 많으면 위의 "연결마다 작업 하나" 방식을 쓰세요.
- 요청 본문(POST body)은 헤더 끝까지만 모으므로 큰 본문은 일부만 들어올 수 있습니다.
- 요청끼리 변수를 공유하지 않습니다(요청마다 격리 실행). 핸들러에서 던진 에러는 경고를 찍고 그 연결만 닫습니다.

| | 연결마다 `spawn` | `serve_event` |
|---|---|---|
| CPU 많이 쓰는 핸들러 | 강함 (여러 코어) | 약함 (루프가 멈춤) |
| 유휴 연결 수천 개 | 약함 (연결당 작업자) | 강함 |
| 요청 본문 | 직접 읽음 | 헤더까지만 |

웹 프레임워크 수준의 라우팅·미들웨어는 언어에 포함되어 있지 않습니다. 위 기본 함수로 직접 만들거나 패키지로 가져오세요.
