# 동시성

bang의 핵심입니다. 규칙은 네 가지뿐입니다.

1. `spawn 식`은 식을 **새 작업**으로 실행하고 결과 자리표(Future)를 바로 돌려줍니다.
2. 그 결과가 **값으로 필요한 순간 자동으로 기다립니다**. `await`가 없습니다.
3. 모든 작업은 자기를 시작한 **함수 본문이나 `parallel { }` 블록이 끝날 때까지** 반드시 끝납니다. 잊힌 작업은 생길 수 없습니다.
4. 리스트·맵·문자열은 작업 사이에 **복사**됩니다. 작업끼리 값을 주고받는 통로는 **채널**과 **작업의 반환값**뿐입니다.

작업은 OS 스레드 풀(M:N 스케줄러)에서 돌고 GIL이 없으므로 CPU 작업도 실제로 여러 코어에서 동시에 실행됩니다.

## spawn과 자동 대기

```bang
fn slow_square(x) {
    sleep(200)               // 0.2초 걸리는 작업이라고 치자
    return x * x
}

let start = now_ms()
let a = spawn slow_square(3)  // 바로 반환 — 기다리지 않음
let b = spawn slow_square(4)  // 이것도 바로 반환
print(a + b)                  // 여기서 둘 다 기다림
print(now_ms() - start < 350) // 0.4초가 아니라 약 0.2초
```

출력:

```text
25
true
```

자동으로 기다리는 곳: 연산자의 피연산자, 함수 호출 인자, `return`, 인덱스·필드 접근 대상, `if`/`while` 조건, `for` 순회 대상. `print`는 표시를 위해 안쪽까지 기다립니다.

명시적으로 기다리려면 `wait(f)`를 씁니다.

```bang
let f = spawn (6 * 7)          // 식 전체를 spawn하려면 괄호
print(f, wait(f) == 42)
```

출력:

```text
42 true
```

`spawn fib(n) + 1`은 `(spawn fib(n)) + 1`로 읽힙니다. 산술식 전체를 새 작업으로 돌리려면 `spawn (a + b)`처럼 괄호로 감싸세요.

### 자동 대기는 얕다

리스트·맵 **안에 넣은** Future는 넣을 때 기다리지 않고, 꺼내 쓸 때 기다립니다. 그래서 Future를 담은 리스트끼리 비교하면 예상과 다를 수 있습니다.

```bang
fn three() { return 3 }
print([spawn three()] == [3])          // 리스트 안의 Future와 3을 비교
print([wait(spawn three())] == [3])    // 먼저 꺼내면 같다
```

출력:

```text
false
true
```

## parallel_map — 가장 자주 쓰는 형태

리스트의 각 원소를 병렬로 처리하고, 결과를 **원래 순서대로** 모읍니다.

```bang
fn fetch(id) {
    sleep(100)
    return {"id": id, "name": f"user{id}"}
}

let start = now_ms()
let users = parallel_map([1, 2, 3, 4, 5, 6, 7, 8], fetch)
print(len(users), users[0].name, users[7].name)
print(now_ms() - start < 500)   // 8 × 0.1초 = 0.8초가 아니라 약 0.1초
```

출력:

```text
8 user1 user8
true
```

- 원소마다 별도의 작업에서 실행됩니다(최대 256개 작업, 원소가 더 많으면 구간으로 나눠 처리).
- 하나라도 에러가 나면 **모두 끝난 뒤** 순서상 첫 에러를 던집니다.

## parallel 블록

블록 안에서 시작한 작업이 모두 끝나야 블록을 빠져나갑니다.

```bang
fn job(name, ms) {
    sleep(ms)
    return name + " 완료"
}

let results = []
parallel {
    let a = spawn job("A", 100)
    let b = spawn job("B", 50)
    results = [a, b]
}
print(results)
```

출력:

```text
[A 완료, B 완료]
```

## 구조적 동시성: 함수는 자식을 기다린다

`parallel` 블록 밖의 `spawn`은 그것을 실행한 **함수 본문**에 속합니다. 함수는 반환하기 전에 자기가 시작한 작업을 모두 기다립니다.

```bang
fn work() {
    spawn fn() {
        sleep(100)
        print("자식 작업 끝")
    }()
    print("work 반환 직전")
    return "work 끝"
}
print(work())
```

출력:

```text
work 반환 직전
자식 작업 끝
work 끝
```

그래서 "백그라운드에 던져 두고 잊는" 작업은 없습니다. 오래 도는 작업은 최상위나 바깥 함수에서 시작하세요. 최상위 코드의 작업은 프로그램이 끝날 때 기다립니다.

## 작업의 에러

작업 안의 에러는 사라지지 않습니다.

- 결과를 값으로 쓰는 순간 그 자리에서 에러가 납니다.
- 아무도 결과를 받지 않았다면, 작업이 속한 함수·블록이 끝날 때 에러를 던집니다.
- 어디서든 `try`/`catch`로 잡을 수 있고, 끝까지 안 잡히면 프로그램이 종료 코드 1로 끝납니다.

```bang
fn risky(x) {
    if x == 0 { throw "0은 안 됨" }
    return 10 / x
}
fn fire_and_forget() {
    spawn risky(0)        // 결과를 아무도 안 받음
    return "반환"
}

try {
    let v = spawn risky(0)
    print(v + 1)          // 값으로 쓰는 순간
} catch e {
    print("값을 쓸 때 잡음")
}
try {
    fire_and_forget()     // 함수가 끝날 때
} catch e {
    print("함수 끝에서 잡음")
}
try {
    print(parallel_map([1, 0], fn(n) { return 10 / n }))
} catch e {
    print(e.kind, e.message)
}
```

출력:

```text
값을 쓸 때 잡음
함수 끝에서 잡음
zero_division 0으로 나눌 수 없음
```

작업 안에서 `throw`한 값은 작업 밖의 `catch`에 **원래 값 그대로** 도착합니다(내장 에러는 언제나처럼 `{kind, message, line, col}` 맵).

```bang
fn fetch(id) {
    if id == 3 { throw {"id": id, "reason": "없는 사용자"} }
    return f"user{id}"
}
try {
    print(parallel_map([1, 2, 3], fetch))
} catch e {
    print(e.id, e.reason)
}
```

출력:

```text
3 없는 사용자
```

## 작업 사이에 공유되는 것은 없다

`spawn`에 넘기는 값과 클로저가 붙잡은 변수는 모두 새 작업용으로 **복사**됩니다. 한 작업이 바꿔도 다른 작업에는 보이지 않습니다.

```bang
let data = [1, 2, 3]
let f = spawn fn() {
    data += [4]           // 작업 안의 복사본을 바꿈
    return data
}()
print(f, data)            // 바깥 data는 그대로

fn make_counter() {
    let n = 0
    return fn() {
        n += 1
        return n
    }
}
let counter = make_counter()
counter()                         // n = 1
print(wait(spawn counter()))      // 작업 안 복사본: 1 → 2
print(counter())                  // 바깥은 영향 없음: 1 → 2
```

출력:

```text
[1, 2, 3, 4] [1, 2, 3]
2
2
```

결과를 모으려면 작업의 **반환값**을 쓰거나 **채널**로 보내세요. 이 규칙 덕분에 락이 필요 없고, 데이터 경쟁이 일어날 수 없습니다. (파일·소켓처럼 바깥 세계의 자원은 원래 공유됩니다.)

## 채널

작업 사이에 값을 흘려보내는 통로입니다. 버퍼 크기 제한은 없습니다.

```bang
fn producer(ch, n) {
    for i in range(n) {
        send(ch, i * 10)
    }
    close(ch)                // 다 보냈으면 닫기
}

let ch = channel()
spawn producer(ch, 3)
for v in ch {                // 닫힐 때까지 받기
    print("받음", v)
}
print(recv(ch))              // 닫힌 채널에서 받으면 nil
```

출력:

```text
받음 0
받음 10
받음 20
nil
```

| 함수 | 설명 |
|---|---|
| `channel()` | 새 채널 |
| `send(ch, v)` | 보내기 (값은 복사됨) |
| `recv(ch)` | 받기 — 값이 올 때까지 기다림, 닫히고 비었으면 `nil` |
| `close(ch)` | 닫기 |
| `for v in ch` | 닫힐 때까지 받기 |
| `select([ch1, ch2])` | 먼저 값이 온 채널에서 받아 `[위치, 값]`, 모두 닫히면 `nil` |

채널로는 **데이터만** 보낼 수 있습니다(int, float, bool, str, bytes, nil, list, map). 함수·채널·Future를 보내면 에러입니다.

### 작업자 풀 예

```bang
fn worker(id, jobs, results) {
    for n in jobs {
        send(results, [id, n * n])
    }
}

let jobs = channel()
let results = channel()
parallel {
    for id in range(3) {
        spawn worker(id, jobs, results)
    }
    for n in range(1, 7) {
        send(jobs, n)
    }
    close(jobs)
}
close(results)

let total = 0
for r in results {
    total += r[1]
}
print(total)     // 1+4+9+16+25+36
```

출력:

```text
91
```

### select

```bang
let fast = channel()
let slow = channel()
spawn fn() {
    sleep(200)
    send(slow, "느림")
}()
spawn fn() {
    sleep(10)
    send(fast, "빠름")
}()
print(select([slow, fast]))    // [위치, 값]
print(recv(slow))
```

출력:

```text
[1, 빠름]
느림
```

## 언제 무엇을 쓰나

| 상황 | 도구 |
|---|---|
| 리스트의 각 원소를 병렬 처리 | `parallel_map(xs, f)` |
| 서로 다른 일 몇 개를 동시에 | `spawn` 여러 개 (+ 필요하면 `parallel { }`) |
| 생산자/소비자, 스트리밍 | 채널 |
| 여러 출처 중 먼저 온 것 | `select` |
| 동시 접속 서버 | [네트워킹](네트워킹) |

## 성능에 대해 정직하게

- 거친 단위의 CPU 작업(작업 하나가 수 ms 이상)은 코어 수에 비례해 빨라집니다. 벤치마크에서 재귀 fib 병렬이 자기 순차 대비 약 4.7배였습니다.
- 순차 실행 속도 자체는 CPython보다 느립니다(재귀 fib 기준 약 3.9배). 아주 잘게 쪼갠 작업은 작업 생성 비용이 이득을 넘을 수 있습니다.
- 자세한 수치: [bench/README.md](https://github.com/knoxxr/bang/blob/main/bench/README.md)
