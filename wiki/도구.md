# 도구 (명령어)

```text
bang <파일.bang> [인자...]       실행 (bang run <파일> 과 같음)
bang --sandbox <파일>            권한 모드로 실행 (아래 "권한 모드")
bang -                           표준 입력의 코드 실행
bang                             REPL (bang repl 과 같음)
bang check [--json] <파일>       실행하지 않고 검사 (--json: 기계가 읽는 진단)
bang test [권한] [경로...]       테스트 실행
bang fmt [--check] [경로...]     들여쓰기 정리
bang new <디렉터리>              새 프로젝트
bang add <이름> <git-url[@rev]>  의존성 추가
bang install                     bang.toml의 의존성 전부 받기
bang compile -o <출력> <파일>    [실험적] 네이티브 실행 파일로 컴파일
bang build <파일>                컴파일만 해 보고 통계 출력
bang parse <파일>                AST 출력 (디버그)
bang tokenize <파일>             토큰 출력 (디버그)
bang --version                   버전
```

## bang run

```sh
bang hello.bang
bang run hello.bang
bang run --dump-ast hello.bang   # 실행 대신 AST 출력
```

프로그램이 끝나면 종료 코드 0, 잡히지 않은 에러가 있으면 1, `exit(n)`을 부르면 `n`입니다. 출력 파이프가 닫히면(`bang x.bang | head`) 조용히 141로 끝납니다.

### 권한 모드 — AI가 쓴 코드를 안심하고 실행

`--sandbox`나 `--allow-*` 플래그를 하나라도 주면 **허가한 것만** 할 수 있습니다. 플래그가 없으면 지금처럼 모두 허용됩니다. 플래그는 스크립트 파일 **앞**에 씁니다.

```sh
bang --sandbox generated.bang
bang run --allow-read=./data --allow-write=./out --allow-net=api.anthropic.com --allow-env=ANTHROPIC_API_KEY agent.bang
```

| 플래그 | 허가하는 것 | 목록 항목 |
|---|---|---|
| `--sandbox` | 아무것도 | — |
| `--allow-read[=경로,..]` | 파일 읽기 (`read_file`, `list_dir`, `file_exists` 등) | 그 경로 아래 전부 |
| `--allow-write[=경로,..]` | 파일 쓰기·삭제·이동·디렉터리 생성 | 그 경로 아래 전부 |
| `--allow-net[=호스트[:포트],..]` | `http_*`, `tcp_connect`, `tcp_listen`, `serve_event` | `api.example.com` 또는 `localhost:8080` |
| `--allow-run[=프로그램,..]` | `proc_run` | 프로그램 이름 (`git`, `ls`) |
| `--allow-env[=이름,..]` | `env_get` | 환경 변수 이름 |
| `--allow-all` | 전부 | — |

값 없이 쓰면(`--allow-read`) 그 분야 전부를 허가합니다. 허가하지 않은 접근은 `permission` 에러가 되고, 메시지에 허용하는 방법이 나옵니다.

<!-- norun -->
```bang
// agent.bang
print(read_file("data/input.txt"))
print(read_file("/home/me/.ssh/id_ed25519"))
```

```text
$ bang --allow-read=./data agent.bang
(data/input.txt 내용)
[3:7] 런타임 오류: 권한 없음: read_file()의 read '/home/me/.ssh/id_ed25519' — 허용하려면 --allow-read=/home/me/.ssh/id_ed25519 (또는 상위 디렉터리)
```

- 경로는 `..`와 심볼릭 링크를 풀어서 비교하므로 `data/../secret`이나 `data` 안의 링크로 빠져나갈 수 없습니다.
- `spawn`한 작업, `map` 같은 콜백, 메서드 문법(`"x".read_file()`), import한 모듈 — 어떤 경로로 불러도 같은 검사를 받습니다.
- 네트워크 호스트는 이름 그대로 비교합니다(`localhost`와 `127.0.0.1`은 다름).
- **OS 수준 격리가 아닙니다.** `--allow-run=sh`처럼 아무 명령이나 실행할 수 있는 프로그램을 허가하면 그 프로세스는 제한을 받지 않습니다. CPU·메모리·시간 제한도 없습니다. 완전한 격리가 필요하면 컨테이너와 함께 쓰세요.

## bang repl

[설치와 첫 실행 → REPL](설치와-첫-실행#repl)을 보세요. 정의한 변수·함수가 세션 내내 유지되고 에러가 나도 세션이 계속됩니다. 값을 보려면 `print`를 쓰세요.

## bang check

파스 오류, 정의되지 않은 이름, 인자 수 불일치, 타입 힌트 충돌을 실행 없이 찾습니다. 문제가 있으면 종료 코드 1입니다. [타입 힌트](타입-힌트#bang-check) 참고.

### JSON 진단 (AI 에이전트·편집기용)

`--json`을 주면 진단 하나를 JSON 한 줄로 냅니다. `bang check --json`은 stdout으로(문제가 없으면 아무것도 출력하지 않고 종료 코드 0), `bang run --json`은 stderr로 냅니다(프로그램 출력은 그대로).

```text
$ bang check --json app.bang
{"severity":"error","stage":"resolve","kind":null,"message":"정의되지 않은 변수: 'None'","file":"app.bang","line":3,"col":9,"hint":"값이 없음은 `nil`"}
```

필드: `severity`(error/warning), `stage`(lex·parse·resolve·type·compile·runtime), `kind`(런타임 오류 종류, 그 밖에는 null), `message`, `file`, `line`, `col`, `hint`(다른 언어 습관 힌트 또는 null). AI 에이전트가 코드를 고치는 반복에서 이 출력을 그대로 읽으면 됩니다.

## bang test

`*_test.bang` 또는 `test_*.bang` 파일에서 `test_`로 시작하는 최상위 함수를 찾아 실행합니다. 경로를 주지 않으면 현재 디렉터리 아래를 모두 찾습니다(`bang_modules/`, `.git/`, `target/` 제외).

<!-- file: calc.bang -->
```bang
// calc.bang
fn add(a, b) {
    return a + b
}
fn mean(xs) {
    return sum(xs) / len(xs)
}
```

<!-- check -->
```bang
// calc_test.bang
let calc = import("calc.bang")

fn test_add() {
    assert_eq(calc.add(2, 3), 5)
}

fn test_mean() {
    assert_eq(calc.mean([1, 2, 3]), 2.0)
}

fn test_empty_mean_fails() {
    try {
        calc.mean([])
        assert(false, "에러가 나야 함")
    } catch e {
        assert_eq(e.kind, "zero_division")
    }
}
```

```text
$ bang test
./calc_test.bang
  ok    test_add
  ok    test_mean
  ok    test_empty_mean_fails

결과: 3개 통과, 0개 실패 (1개 파일, 3ms)
```

실패하면 위치와 차이를 보여 주고 종료 코드 1로 끝납니다.

```text
./calc_test.bang
  FAIL  test_add
        [4:5] 런타임 오류: assert_eq 실패: 기대 6, 실제 5
          |
          4 |     assert_eq(calc.add(2, 3), 6)
          |     ^
  ok    test_mean
  ok    test_empty_mean_fails

결과: 2개 통과, 1개 실패 (1개 파일, 0ms)
```

- 파일의 최상위 코드는 한 번 실행되고, 각 테스트 함수는 서로 **격리된 상태**에서 선언 순서대로 실행됩니다. 한 테스트가 전역 변수를 바꿔도 다음 테스트에 영향이 없습니다.
- `assert_eq(실제, 기대)`는 리스트·맵을 내용으로 비교합니다(맵은 순서 무관). `1 == 1.0`처럼 정수와 실수는 같은 값이면 같다고 봅니다.
- 에러가 나는지 확인하려면 위의 `test_empty_mean_fails`처럼 `try`/`catch`를 씁니다.
- 권한 플래그도 받습니다: `bang test --sandbox --allow-read=fixtures`. AI가 만든 코드를 테스트할 때 유용합니다.

## bang fmt

들여쓰기를 4칸으로 맞추고, 줄 끝 공백·연속된 빈 줄·CRLF를 정리합니다. 줄을 합치거나 나누지는 않습니다.

```sh
bang fmt                 # 현재 디렉터리 아래 .bang 파일을 모두 고침
bang fmt src/main.bang   # 특정 파일만
bang fmt --check         # 고치지 않고 검사만 — 고칠 파일이 있으면 종료 코드 1 (CI용)
```

```text
$ bang fmt --check
포맷 필요: ./messy.bang
1개 파일이 포맷되지 않았습니다 (bang fmt로 고치세요)
```

포맷 전후의 토큰이 같은지 확인한 뒤에만 파일을 씁니다. 코드의 의미를 바꿀 위험이 없습니다.

## bang compile (실험적)

bang 코드를 C로 옮겨 시스템 C 컴파일러(`cc`, `clang`, `gcc`)로 네이티브 실행 파일을 만듭니다.

```sh
$ bang compile -o fib fib.bang
컴파일 완료: fib.bang → fib
$ ./fib
832040
```

- **지원하는 것**: 정수·실수·불리언·문자열·`nil`, 산술·비교·논리, `let`/대입/복합 대입, `if`/`while`/`return`, 최상위 함수(재귀 포함), 내장 함수 16개(`print` `len` `str` `int` `float` `bool` `abs` `min` `max` `floor` `ceil` `round` `sqrt` `pow` `assert` `exit`).
- **지원하지 않는 것**: 리스트, 맵, 인덱스, `for`, 클로저, `spawn`/`parallel`, `try`/`catch`, f-문자열, 타입 힌트, 기본값 매개변수 등. 이런 코드는 조용히 틀리게 컴파일되지 않고 **위치를 짚은 에러**로 거절됩니다.

```text
[6:7] AOT 오류: AOT: f-문자열 미지원 (+ 와 str() 사용)
  |
  6 | print(f"done")
  |       ^
```

- 지원 범위 안에서는 출력·종료 코드·에러 메시지가 VM과 글자 단위로 같도록 테스트로 보장합니다.
- 재귀 `fib(30)`이 VM에서 약 0.6초, 컴파일 결과물은 약 0.01초였습니다. 숫자 위주 핫 루프를 따로 떼어 낼 때 쓸 만합니다.
- Windows에서는 MinGW `gcc`나 `clang`이 필요합니다(MSVC `cl`은 지원하지 않음).

## bang build / parse / tokenize

```text
$ bang build calc.bang
빌드 완료: calc.bang
  전역: 2개  상수 풀: 2개  메인 opcode: 16바이트
```

`parse`와 `tokenize`는 언어 자체를 디버깅할 때 쓰는 명령입니다.
