# bang 활성화 계획 — 철학과 실행

> 이 문서는 bang이 "만들어진 언어"에서 "쓰이는 언어"가 되기 위한 철학적 토대와
> 실행 계획이다. 철학 없는 실행은 정체성 희석으로, 실행 없는 철학은 무관심으로
> 죽는다 — 둘은 한 문서여야 한다.
>
> (작성 근거: 철학·언어채택사·GTM 3개 관점의 독립 분석을 교차 검증해 종합.
> 상충 지점은 본문에 결정과 이유를 명시했다.)

---

## 1. 정체성 — 한 문장

**bang은 "동시성은 배우는 것이 아니라 잊어도 되는 것"임을 증명하기 위해 존재한다.**

순차적으로 생각하고 쓰면, 병렬로 실행된다. `spawn` 한 단어가 동시성 커리큘럼의
전부다. 이것이 가능한 이유는 언어가 동시성을 어렵게 만드는 단 하나 —
공유 가변 상태 — 를 문법 이전 단계에서 제거했기 때문이다.

세계관: **멀티코어 시대에도 스크립팅의 순차적 정신 모델은 죽지 않아도 된다.**

## 2. 철학 — 4기둥

bang의 철학은 새로 만드는 것이 아니라 이미 저장소 전체에 살아 있는 것을
명문화하는 것이다 (CLAUDE.md 불변 규칙, SPEC 6.1, 25릴리스의 실제 결정들):

1. **값의 절대성** — 컨테이너(list/map/string)는 값이다. 어떤 성능 목표도
   공유 가변 참조를 정당화하지 못한다. `push`/`sort`가 새 값을 반환하는
   stdlib까지 이 공리로 일관한다.
2. **의미는 계약, 구현은 소모품** — 실행 백엔드가 OS스레드→M:N풀→탄력풀→리액터로
   세 번 교체되는 동안 관찰 가능한 의미는 한 번도 변하지 않았다(Phase 3→9→28→35).
   최적화는 관찰 불가능할 때만 허용된다(Phase 14 COW가 선례).
3. **자급 코어** — JSON·정규식·시간·난수·HTTP를 자체 구현한다. 의존성은 증명된
   필요에만(현재 polling + https용 rustls/webpki-roots — TLS는 기능 플래그로 뺄 수 있음). 이것은 비효율이 아니라 "이 언어는 통째로 이해
   가능하다"는 교육적 자산이다.
4. **정직한 한계 문서화** — 한계는 기능과 같은 크기로 적는다(SPEC 6.4-3
   "한계 (반드시 인지)" 스타일). 사용자 0명 단계에서 유일하게 축적 가능한
   신뢰 자산은 정직뿐이다.

### 헌법 조항 (요약 9조)

1. 값의 절대성 (위 1기둥)
2. **단색 함수**: 함수는 하나의 색만 갖는다 — async/await류 함수 분열을 영원히 도입하지 않는다
3. **뿌리내린 작업**: 작업 누수는 버그가 아니라 불가능이어야 한다 — fire-and-forget 프리미티브 금지
4. 의미는 계약 (위 2기둥) — 의미 변경은 SPEC과 같은 커밋에서
5. 자급 코어 (위 3기둥)
6. **작은 표면**: 키워드는 최후의 수단, 기능은 함수로 먼저 (channel/send/recv가 함수인 이유)
7. **에러는 사람에게**: 모든 에러에 (line,col)과 소스 문맥. 조용한 wrap·조용한 마법 금지
8. 정직한 문서 (위 4기둥)
9. **점진성**: 타입·검사는 opt-in. 힌트 없는 코드는 영원히 유효하다

### 영구 거부 목록 (anti-goals)

bang의 진짜 발명은 '빼기'다. 아래는 요청이 와도 영원히 추가하지 않는다:

- async/await (색칠은 옵션이어도 생태계를 sync/async로 두 쪽 낸다 — `wait()`로 충분)
- 락·뮤텍스의 사용자 노출
- 컨테이너 공유 가변 참조 (내부 최적화로도 관찰 가능해지면 금지)
- 클래스·상속 (맵+클로저는 값 의미론과 짝을 이루는 설계지, 편의 기능의 부재가 아니다)
- 매크로/메타프로그래밍
- 중앙 패키지 레지스트리 운영 (git이 레지스트리다)
- 암묵 변환·bigint 자동 승격 (오버플로는 정직한 에러)
- "모두를 위한 언어" 포지셔닝

> 거절된 제안은 이 문서 부록에 한 줄씩 축적한다. 살아있는 언어의 증거는
> 수용 이력이 아니라 **일관된 거절 이력**이다.

### 격언 (한/영 병기)

1. 모든 함수는 같은 색이다 — *Every function is the same color.*
2. 값은 복제되고, 두려움은 복제되지 않는다 — *Values are copied; fear is not.*
3. 공유할 수 없으면 경쟁할 수도 없다 — *What cannot be shared cannot race.*
4. 기다림은 당신의 일이 아니다 — *Waiting is not your job.*
5. 모든 작업은 스코프에 뿌리내린다 — *Every task takes root in a scope.*
6. 한계는 기능만큼 크게 적는다 — *Write the limits as large as the features.*

## 3. 누구를 위한 언어인가

모두를 위한 언어는 아무도 안 쓴다.

**주 페르소나 — "GIL 난민"**: Python으로 CPU 바운드 스크립트(배치 처리, 파일
대량 변환, 스크래핑 후처리)를 쓰다가 multiprocessing의 pickle 지옥과 asyncio
색칠에 지친 스크립터. "일요일 오후에 8코어를 다 쓰고 싶은 사람."

**부 페르소나**: (a) 락·레이스 없이 동시성 개념을 가르치려는 교육자 — 언어가
작아 한 학기에 전부 다룰 수 있다. (b) 모국어 에러 메시지가 필요한 한국어권 입문자.

**비-페르소나 (정직하게 명시)**: 대규모 프로덕션 팀, 순차 성능 극한 추구자,
거대 생태계(numpy 등) 의존자. 이들에게 bang을 권하지 않는 것이 신뢰의 시작이다.

## 4. 정직한 포지셔닝

**말할 것**: "스크립트 체급에서, 색칠 없이, 값 의미론으로 레이스를 원천 제거한
병렬성." 비교물은 실행 속도가 아니라 **코드 대 코드**다 — Python asyncio+lock
25줄 vs bang 6줄.

**말하지 않을 것**:
- "Python보다 빠르다" — 순차 성능은 CPython보다 3~4배 느리다. 이 주장은 첫
  독립 벤치마크에서 반박당하고, 신생 언어는 잃은 신뢰를 회복할 기회가 없다.
- "Python 대체재" — Python이 못 하는 단 한 가지(색칠 없는 진짜 병렬)로만 말한다.
- "동시성 언어" 단독 — Go/Elixir와 정면 비교당해 진다. 반드시 세분화된 문장으로.

**성능 재프레임**: bang의 성능 단위는 코어 1개가 아니라 머신 전체다.
"한 코어에서는 지고, 여덟 코어에서는 이긴다"를 먼저 말하는 것이 최고의 방어다.

## 5. 역사에서 배운 전제

- 생존한 소수 언어의 티핑포인트는 전부 **언어 밖**에서 왔다: Lua(임베딩 유통),
  Ruby(영어책+Rails), Elixir(BEAM+Phoenix), Clojure(JVM 기생). 기술적 완성도가
  티핑포인트였던 사례는 없다.
- 죽은 언어의 사인은 기술 부족이 아니라 **포지셔닝 실패**다: Io(감탄 후 이탈 —
  "이것으로만 풀 수 있는 문제" 부재), Reia(bang과 가장 유사한 1인 동시성 언어 —
  같은 니치의 Elixir 등장에 저자가 접음).
- 사용자는 언어를 배우러 오지 않는다 — **앱을 쓰러 왔다가 언어에 남는다**
  (Rails의 15분 블로그). 킬러 데모는 언어 고유 의미론에서 유래해야 모방 불가다.
- 0→100명 구간에서 작동한 것은 세 가지뿐: 30분 내 '와'가 나오는 고유 데모,
  한계를 명시한 정직한 런치 포스트, 저자의 즉각 응답. **이 구간에서 기능 추가가
  사용자를 만든 사례는 없다.**
- 100→1000명 분기점은 bus factor 2 (첫 외부 기여자·타인의 프로덕션 증언).
- 2026년 신규 변수: LLM 훈련 데이터 0인 언어는 "LLM이 못 쓰는 언어"라는 새
  장벽을 갖는다. 역으로 bang은 문법이 작아 컨텍스트 학습으로 커버 가능 —
  역사상 어떤 신생 언어도 갖지 못한 저비용 레버.

## 6. 언어 전략 결정 — 한국어와 영어

세 분석이 상충한 지점. 결정과 이유:

- **결정: 한국어 1차 언어 유지 + 영어 관문 1장 + 한국어 채널 선(先)런치.**
- 이유: (a) 한국어 문서(TUTORIAL/SPEC)가 이미 완비돼 국내 런치는 준비 비용 0,
  (b) "한국어가 1차 언어인 유일한 실용 범용 언어"는 방어 가능한 독점 범주
  (Ruby-1995 전략), (c) 전면 영어화는 1인 개발자에게 유지비 재앙.
- 단, **영어 관문 0장은 자충수다** (GitHub/HN/LLM 노출 원천 차단). 정체성 문장·
  격언·설치·spawn 데모·한계만 담은 README.en.md 1장이 최소 조건이며, HN 런치
  전 필수다. TUTORIAL/SPEC은 번역하지 않는다 — 이 결정 자체를 여기 기록한다.
- 에러 메시지는 한국어 기본 유지, 장기적으로 에러 코드([E012]) 병기 후
  `BANG_LANG=en` 로케일 옵션 검토 (P2).

## 7. 실행 계획

### 7.0 시간 배분 원칙

**향후 3개월: 코드 30% / 문서·데모·커뮤니티 70%.**
35개 Phase 동안 사용자 0이라는 사실이 이미 진단이다. Phase 36을 만들기 전에
배포·설득이 먼저다. (예외: 아래 P0의 http_get — 이것은 데모를 해금하는 코드다.)

### 7.1 P0 — 런치 재료 (순서대로)

1. **`http_get`/`tcp_connect` 빌트인 추가** — 아웃바운드 네트워킹이 현재 전무해
   spawn의 가장 바이럴한 데모(API 팬아웃/동시 스크래핑)가 작성 불가능하다.
   std::net 위 최소 HTTP/1.1 클라이언트(자급 코어 원칙 준수, TLS는 1차 제외+한계 명시).
   `examples/fanout.bang`: `parallel_map(urls, fn(u){ http_get(u) })` 4줄 vs
   Python aiohttp ~25줄 나란히.
2. **README 첫 화면 재구성** — 현재 첫 문단은 구현 이력(만든 사람의 자부심)이고
   첫 코드는 131행의 fibonacci다. 교체: 1행 정체성 문장 → spawn 3줄 데모+실측
   출력 → brew 설치 한 줄. 구현 이력은 하단으로.
3. **정직 벤치마크 페이지** — bench/에 (1) 순차 fib: CPython 대비 3-4x 느림을
   표 첫 줄에 명기, (2) 코어 스케일링 곡선(4.4x), (3) I/O-bound 벽시계 승리,
   (4) 재현 스크립트+하드웨어 명세. **지는 항목을 먼저 쓴다.**
4. **docs/PHILOSOPHY.md 제정** — 이 문서 2장(헌법+거부 목록+격언)을 사용자 대면
   문서로 승격. CONTRIBUTING에서 링크.
5. **런치 시퀀스** (재료 완비 후):
   - 1차 **GeekNews** (한국어, 홈그라운드): "1인+AI 페어로 8개월, async 없는
     병렬 언어를 Rust로 바닥부터" — 만든 과정+데모 혼합 각도
   - 첫 20~30명 피드백으로 온보딩 갭 수정 (시간차 필수)
   - **README.en.md 1장** 작성 후 2차 **Show HN**: "Show HN: Bang – a language
     where spawn is the whole concurrency story" — 6줄 데모, 한계 3줄, 정직 벤치 링크
   - 3차 **r/ProgrammingLanguages** (마케팅 적대 문화 — 설계 노트 각도만):
     "Transparent concurrency via value semantics: auto-join points and tradeoffs"
   - 게시 후 48시간 모든 댓글·이슈 즉각 응답. 첫 포스트가 묻혀도 실패가 아니다
     (Zig·Elixir도 그랬다) — 작동하는 것은 6~12개월 간격의 반복 노출이다.
