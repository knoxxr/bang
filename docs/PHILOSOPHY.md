# bang 헌법 (The bang Constitution)

> 이 문서는 bang이 **무엇이며 무엇이 아닌지**를 정한다. 기능 목록이 아니라 세계관이다.
> 1인 언어에서 철학의 가치는 옳음이 아니라 **일관성**이다 — 그래서 이 문서는
> "무엇을 할지"보다 "무엇을 영원히 안 할지"에 더 많은 지면을 쓴다.
>
> 활성화 실행 계획은 [VISION.md](VISION.md)에, 개발 규율은 저장소 CLAUDE.md에 있다.

## 정체성 — 한 문장

**bang은 "동시성은 배우는 것이 아니라 잊어도 되는 것"임을 증명하기 위해 존재한다.**

순차적으로 생각하고 쓰면, 병렬로 실행된다. `spawn` 한 단어가 동시성 커리큘럼의
전부다. 이것이 가능한 이유는 언어가 동시성을 어렵게 만드는 단 하나 —
공유 가변 상태 — 를 문법 이전 단계에서 제거했기 때문이다.

## 격언

1. 모든 함수는 같은 색이다 — *Every function is the same color.*
2. 값은 복제되고, 두려움은 복제되지 않는다 — *Values are copied; fear is not.*
3. 공유할 수 없으면 경쟁할 수도 없다 — *What cannot be shared cannot race.*
4. 기다림은 당신의 일이 아니다 — *Waiting is not your job.*
5. 모든 작업은 스코프에 뿌리내린다 — *Every task takes root in a scope.*
6. 한계는 기능만큼 크게 적는다 — *Write the limits as large as the features.*

## 조항 (9조)

1. **값의 절대성** — 컨테이너(list/map/string)는 값이다. 바인딩·인자·반환·
   채널 송신·spawn에서 모두 복제된다. **어떤 성능 목표도 작업 사이의 공유 가변 참조를
   정당화하지 못한다.** (관찰 불가능한 최적화, 예: copy-on-write는 허용 — 관찰되는
   의미가 깊은 복사와 동일한 한.)
   클로저는 값이 아니라 **변수**를 붙잡는다 — 한 작업 안에서 같은 변수를 붙잡은 클로저끼리
   상태를 공유한다(Python과 같은 늦은 바인딩, "맵 + 클로저 객체"의 근거). 대신 작업 경계
   (spawn·parallel_map)를 넘는 값은 그 안에 든 클로저와 클로저 상태까지 통째로 복사되므로,
   **작업 사이에는 어떤 가변 상태도 공유되지 않는다.** (2026-11 개정, Phase 53 — 이전 문구
   "클로저 캡처에서 복제"는 구현과 달랐고, 인자 안의 객체가 작업 사이에 공유되는 결함이 있었다.)
2. **단색 함수** — 함수는 하나의 색만 갖는다. async/await류 함수 분열을 도입하지 않는다.
3. **뿌리내린 작업** — 모든 `spawn`은 가장 가까운 함수 본문이나 `parallel {}` 블록에
   뿌리내리고 스코프 종료 시 자동 조인된다. 작업 누수는 버그가 아니라 불가능이다.
4. **의미는 계약, 구현은 소모품** — 실행 백엔드는 교체 가능하나 관찰 가능한 의미는
   불변이다. 의미 변경은 SPEC과 같은 커밋에서 이뤄진다.
5. **자급 코어** — stdlib는 자체 구현이 기본이다. 의존성은 증명된 필요에만 추가한다.
   (현재 런타임 의존성: 논블로킹 I/O 리액터 `polling` 하나.)
6. **작은 표면** — 키워드는 최후의 수단이다. 기능은 함수로 먼저 시도한다
   (`channel`/`send`/`recv`/`wait`가 키워드가 아니라 함수인 이유).
7. **에러는 사람에게** — 모든 에러에 `(line, col)`과 소스 문맥이 붙는다. 조용한
   wrap도, 조용한 마법도 없다 (정수 오버플로는 조용히 wrap하지 않고 잡히는 에러,
   없는 맵 키 읽기도 조용한 `nil`이 아니라 잡히는 에러 — 2026-11 개정, Phase 48).
   잡힌 내장 에러는 종류(`kind`)를 가진 값이라, 메시지 문자열을 비교하지 않고도 구별할 수 있다.
8. **정직한 문서** — 한계는 기능과 같은 크기로 적는다. 마케팅을 위해 한계를 흐리지 않는다.
9. **점진성** — 타입·검사·최적화는 opt-in이다. 힌트 없는 코드는 영원히 유효하다.

## 영구 거부 목록 (Anti-goals)

bang의 진짜 발명은 '빼기'다. 아래는 요청이 와도 **영원히 추가하지 않는다.**
각 항목은 편의의 부재가 아니라 위 조항과 짝을 이루는 설계 결정이다.

| 거부 | 이유 |
|------|------|
| async/await (옵션이라도) | 색칠은 옵션이어도 생태계를 sync/async로 두 쪽 낸다. 자동 조인 + `wait()`로 충분 (조항 2) |
| 락·뮤텍스의 사용자 노출 | 값 의미론이 공유를 제거했으므로 락이 필요 없다. 채널이 유일한 명시적 공유 통로 (조항 1) |
| 컨테이너 공유 가변 참조 | 관찰 가능해지는 순간 동시성 안전의 공리가 무너진다 (조항 1) |
| 클래스·상속 | 참조 의미론 객체가 생겨 값 의미론과 충돌한다. 맵+클로저로 충분 (조항 1) |
| 매크로·메타프로그래밍 | 언어를 통째로 이해 가능하게 유지한다 (조항 6) |
| 중앙 패키지 레지스트리 운영 | git이 레지스트리다. 운영 부담·중앙 통제를 만들지 않는다 |
| 암묵 변환·bigint 자동 승격 | 조용한 마법 금지. 오버플로는 정직한 에러 (조항 7) |
| 런타임 튜닝 노브 노출 | 의미가 구현 세부에 새지 않게 한다 (조항 4) |
| "모두를 위한 언어" 포지셔닝 | 모두를 위한 언어는 아무도 안 쓴다. bang은 색칠 없는 병렬 스크립팅을 위한 언어다 |

## 누구를 위한 언어인가

- **주 대상**: Python으로 CPU 바운드 스크립트를 쓰다가 GIL·`asyncio` 색칠·
  `multiprocessing` 직렬화에 지친 스크립터.
- **부 대상**: 락·레이스 없이 동시성을 가르치려는 교육자, 모국어 에러가 필요한 입문자.
- **대상이 아님**: 대규모 프로덕션 팀, 순차 성능 극한 추구자, 거대 생태계 의존자.
  이들에게 bang을 권하지 않는 것이 신뢰의 시작이다.

## 언어 정책

bang의 1차 문서 언어는 **한국어**다 (TUTORIAL·SPEC은 한국어 정본).
"한국어가 1차 언어인 유일한 실용 범용 언어"라는 정체성을 지킨다. 단 국제 관문으로
영어 요약 1장(README 영어 섹션)은 유지한다 — TUTORIAL/SPEC 전면 번역은 하지 않는다.

## 거절의 기록

> 헌법·거부 목록에 근거해 거절된 제안을 축적한다. (제안 — 근거 — 대안)

- **Set 내장 타입** — 코어 값 표면 확대 — 리스트 기반 `union`/`intersect`/`difference`로 대체 (Phase 24)
- **코루틴 크레이트(corosensei) 의존성** — 자급 코어(조항 5) — 연결 단위 상태머신을 런타임에 두는 방식 선택 (Phase 35, serve_event)
- **C 라이브러리 호출(FFI)** — 자급 코어(조항 5)·통째로 이해 가능한 언어. FFI는 메모리 안전·값 의미론의
  보장을 언어 밖으로 넘기고, 플랫폼별 빌드를 요구한다 — 외부 프로그램은 `proc_run`으로 호출한다.
  영구 거부가 아니라 **보류**: 실사용자의 구체적 요구가 쌓이면 재검토한다 (2026-11, Phase 48 결정 4)
- **에러 전용 값 타입(Error)** — 작은 표면(조항 6) — `catch e`의 내장 에러는 새 타입 대신 맵
  `{kind, message, line, col}`으로 ("객체 = 맵" 원칙, Set 거절과 같은 근거) (Phase 48)

> 수용 기록 (거절 원칙의 예외와 그 이유):

- **Bytes 값 타입 수용** (Phase 43) — Set과 달리 리스트로 대체할 수 없다: Set은 리스트로 *의미*를
  표현할 수 있었지만, 바이트 열은 str(UTF-8 강제)에도 list(원소당 값 하나 — 1MB 파일이 백만 개의
  Int)에도 담을 수 없어 바이너리 파일·소켓 무손실 처리 자체가 불가능했다. 표면은 최소로 유지:
  불변, 리터럴 문법 없음, 변환 빌트인 6개.
